# 易境技术设计与数据规范

> 版本：v0.1  
> 日期：2026-08-24  
> 状态：MVP 默认方案，可通过架构决策记录（ADR）变更

> 2026-09-05 运行可靠性补充：生产冒烟的服务就绪、路由检查和 `/api/health` 请求共享统一截止时间；`SMOKE_TIMEOUT_MS` 无效时回退到 30 秒，单次请求超时由 `AbortController` 终止，避免部署验收进程无限挂起。

## 1. 技术目标

技术方案需要优先保证以下能力：

1. 卦象和关系卦计算准确、可测试、可解释；
2. 手机与桌面使用同一套代码；
3. 账户登录后在多设备间安全保留学习记录；
4. 内容数据与用户数据分离，方便独立校对与升级；
5. 后续增加账号同步、PWA、干支历法和 AI 时不必推翻 MVP；
6. 每次数据格式变化都有版本与迁移路径。

### 2.2 暂不引入

- 全局状态框架：MVP 优先使用组件状态、Context 和领域 hooks；出现明确跨域状态复杂度后再引入。
- 服务端数据库：已采用 PostgreSQL；Compose 启动时自动执行增量迁移。
- 用户认证：已提供邮箱/密码、HttpOnly 会话 Cookie 和账户级数据隔离。
- 富文本编辑器：MVP 使用纯文本/基础 Markdown，降低数据格式和安全复杂度。
- 通用知识图数据库：当前关系规模使用普通 JSON 和关系表足够。
- 微服务、消息队列、容器编排：不符合个人应用当前规模。

## 4. 卦象数据契约

这是整个项目最重要的技术约定。不同资料对二进制方向和绘图方向的表达可能不同，如果不统一，错卦、综卦、互卦和卦序映射都会产生隐蔽错误。

### 4.1 阴阳编码

```ts
type LineValue = 0 | 1; // 0 = 阴，1 = 阳
```

显示层可以使用断线/实线、文字、图标或 Unicode，但核心计算只使用 `0 | 1`。

### 4.2 爻序方向

所有数组统一按照“从下往上”存储：

```ts
type TrigramLines = readonly [LineValue, LineValue, LineValue];
// 索引 0、1、2 对应下爻、中爻、上爻

type HexagramLines = readonly [
  LineValue, // 初爻
  LineValue, // 二爻
  LineValue, // 三爻
  LineValue, // 四爻
  LineValue, // 五爻
  LineValue, // 上爻
];
```

渲染时可以从数组末尾开始绘制，以便视觉上“上爻在上”；不得为了显示方便改变数据存储方向。

五行工具的静态记录使用稳定 ID、中文名称、展示色、相生目标、相克目标和基础象意；构建校验要求恰好五行、ID/名称不重复、颜色为六位十六进制值，并验证木→火→土→金→水→木的相生环及木克土、火克金、土克水、金克木、水克火的相克映射。该校验只保证学习工具的数据一致性，不据此输出个人吉凶判断。

### 4.3 八卦标准表

以下数组均为从下往上：

| ID   | 卦名 | 三爻数组  | 签名  |
| ---- | ---- | --------- | ----- |
| qian | 乾   | `[1,1,1]` | `111` |
| dui  | 兑   | `[1,1,0]` | `110` |
| li   | 离   | `[1,0,1]` | `101` |
| zhen | 震   | `[1,0,0]` | `100` |
| xun  | 巽   | `[0,1,1]` | `011` |
| kan  | 坎   | `[0,1,0]` | `010` |
| gen  | 艮   | `[0,0,1]` | `001` |
| kun  | 坤   | `[0,0,0]` | `000` |

注意：“签名”只是数组序列化结果，不宣称采用某一文献中的二进制编号法。

### 4.4 上下卦组合

```ts
function composeHexagram(
  lower: TrigramLines,
  upper: TrigramLines,
): HexagramLines {
  return [...lower, ...upper] as HexagramLines;
}
```

因此：

- `hexagram.slice(0, 3)` 是下卦；
- `hexagram.slice(3, 6)` 是上卦；
- 显示页面必须使用“上卦/下卦”文字标签，不只依赖空间位置。

### 4.5 变卦

动爻位置使用 1～6 的领域编号，进入数组操作前转换为 0～5：

```ts
type LinePosition = 1 | 2 | 3 | 4 | 5 | 6;

changed[i] = movingPositions.has(i + 1) ? toggle(original[i]) : original[i];
```

- 空动爻集合时变卦与本卦相同；
- 多爻同时变化，不按点击顺序产生不同结果；
- 点击历史只用于“撤销”，不影响最终计算。

### 4.6 关系卦定义

MVP 使用以下明确规则：

```ts
// 错卦：每一爻阴阳反转
opposite = original.map(toggle);

// 综卦：六爻上下倒置
reversed = [...original].reverse();

// 互卦：二三四爻为下互卦，三四五爻为上互卦
nuclear = [
  original[1],
  original[2],
  original[3],
  original[2],
  original[3],
  original[4],
];
```

如后续需要支持其他定义，必须增加 `ruleSetId`，不得静默修改现有结果。

### 4.7 六十四卦身份

每卦同时拥有多个不同用途的字段：

```ts
interface HexagramIdentity {
  id: string; // 稳定内部 ID，如 hexagram-01
  kingWenNumber: number; // 1..64
  nameZhHans: string;
  unicodeSymbol: string; // 仅显示用
  lowerTrigramId: TrigramId;
  upperTrigramId: TrigramId;
  lines: HexagramLines;
  signature: string; // 六爻数组序列化，便于查找
}
```

约束：

- 路由优先使用文王卦序，内部关联使用稳定 `id`；
- 程序不能依赖 Unicode 顺序计算文王卦序；
- 数据加载时校验 `upper/lower` 与 `lines` 一致；
- 64 个 `signature` 必须唯一且完整覆盖全部组合。

## 5. 内容数据模型

### 5.1 基础概念

```ts
interface Concept {
  id: string;
  slug: string;
  title: string;
  summary: string;
  stageId: string;
  prerequisiteIds: string[];
  relatedConceptIds: string[];
  blocks: ContentBlock[];
  commonConfusions: string[];
  sourceIds: string[];
  exerciseTemplateIds: string[];
  contentVersion: number;
  reviewStatus: "draft" | "reviewed" | "published";
}
```

当前实现保留 body 作为兼容读取字段，同时为每个知识点生成一一对应的 blocks。首批块均标记为 editorial，带有 sourceIds 和“通用基础” traditionTags；构建校验会检查块数量、内容一致性、来源存在性和块 ID 唯一性，详情页按块类型渲染。知识点、内容块、练习、八卦、卦辞和爻辞 schema 均为严格对象，业务 ID 和来源引用必须是原始值已修剪的非空字符串，未知字段会阻止构建，避免内容编辑时的字段漂移被静默剥离。校验器还会阻止 canonical 块引用未核验经典来源，以及 external_view 块引用不适合的来源类型。

### 5.2 内容块

```ts
type ContentKind = "canonical" | "editorial" | "external_view" | "computed";

interface ContentBlock {
  id: string;
  kind: ContentKind;
  title?: string;
  markdown: string;
  sourceIds: string[];
  traditionTags: string[];
  reviewedAt?: string;
}
```

个人笔记不进入 `ContentBlock`，而进入账户数据库，避免发布内容升级时覆盖用户信息。

### 5.4 卦和爻

```ts
interface Hexagram extends HexagramIdentity {
```

MVP 已建立 64 条卦辞和 384 条爻辞的结构化记录；在底本确认前使用 `canonicalText: null` 与 `status: 'pending'`，页面明确显示待校对，不填入未经核验的原文。

### 5.5 来源

```ts
type SourceType = "classic" | "book" | "video" | "web" | "personal";

interface Source {
  id: string;
  type: SourceType;
  title: string;
  author?: string;
  edition?: string;
  publisher?: string;
  year?: string;
  url?: string;
  locator?: string; // 页码、章节或视频时间点
  accessedAt?: string;
  copyrightNote?: string;
  reviewOwner: "content-owner" | "project-maintainer" | "user";
  usePolicy: "verbatim-allowed" | "metadata-only" | "user-supplied";
}
```

来源登记表位于 `content/sources.ts`，同时维护 `SOURCE_CITATION_POLICY`。经典、书籍、视频、网页和个人记录分别声明允许的收录方式；状态为 `needs-review` 的来源可以作为待校对引用存在，但不能为发布内容提供未经确认的经典原文。构建校验会检查来源 ID、收录策略和复核责任人，来源 ID 及所有静态内容来源引用必须是原始值已修剪的非空字符串，来源对象拒绝未声明字段，来源 URL 必须是带主机的 HTTP(S) 地址，来源访问日期必须是真实的 `YYYY-MM-DD` 日期，内容块复核时间（如有）必须是带时区的 ISO 时间戳，避免把自编释义误标为原典或把损坏元数据带入发布数据。

### 5.6 练习模板模式

练习题共享同一套作答与复习记录接口；`mode` 可选为 `immediate` 或 `review`，`responseType` 可选为 `choice` 或 `text`（未声明时默认为 `choice`）。文本题允许 `choices` 为空，并由统一答案归一化函数判定；选择题仍必须包含正确答案，除明确声明的二选一交互题外至少提供三个选项。未声明 `mode` 的题目默认属于即时练习，且每个知识点必须保持 2～5 道即时题；`review` 题目用于覆盖更细的记忆字段，只进入间隔复习队列，不改变知识详情页的即时练习配额。这样可以在新增十天干、十二地支等大量卡片时，保持课程页面短小，同时让长期复习拥有足够的题目变化。

选择题的候选池在生成前按值去重；生成器先尝试使用稳定偏移位置，再继续顺序扫描候选池，直到得到最多三个不同选项。内容守门要求每题选项不得重复，除明确声明的二选一交互题（当前为三爻排列和天干阴阳）外至少有三个选项，并且答案必须在选项中。这样可以避免源数据中存在重复关联值（例如中宫与坤宫均关联坤卦）时，干扰项被去重后只剩两个的问题。

长期统计中的薄弱点改善率从 `ReviewAttempt` 原始记录重算：同一卡片连续两次“忘记”形成一个薄弱点事件，之后 14 个日历日内连续两次非“忘记”评价计为改善；即时练习记录不参与，未形成事件或观察窗口不足时返回 `null`。

视觉偏好使用 `theme`（`light`、`dark`、`system`）和 `fontScale` 两个本地值；`system` 在渲染时解析 `prefers-color-scheme`，并监听系统主题变化，不把系统状态写入用户偏好。

复习偏好使用 `dailyNewCardLimit` 与 `sessionBatchSize`，界面在控件下方实时显示当前值对新卡加入和每组展示数量的影响；到期卡始终优先，参数变化不删除历史作答或修改内置内容。

文字版本属于内容能力而不是通用字符串转换：当前内置内容只有简体字段，偏好页明确提示繁简切换暂不可用，不保存一个无法生效的“繁体”偏好，也不做未经内容负责人复核的自动转换。只有当具体内容同时具备已复核的简体/繁体字段和来源后，才可按内容能力开放切换。

## 6. 用户数据模型

所有时间使用 ISO 8601 保存；“某天到期”另外保存用户本地日期 `YYYY-MM-DD`，避免跨时区和夏令时导致队列漂移。调度器及今日页、即时练习、复习会话、课程完成和统计界面统一调用 `core/date/local.ts` 的 `formatLocalDate`，按本地年月日格式化，不能通过区域化字符串或 `toISOString().slice(0, 10)` 推导到期日。用户可见的备份和内容复核清单文件名也使用该本地日历格式化，避免在午夜附近出现跨日文件名。

### 6.1 笔记

```ts
interface UserNote {
  id: string;
  targetType: "concept" | "trigram" | "hexagram" | "hexagram_line" | "session";
  targetId: string;
  title?: string;
  markdown: string;
  tags: string[];
  sourceRefs: UserSourceRef[];
  createdAt: string;
  updatedAt: string;
  deletedAt?: string;
}

interface UserSourceRef {
  label: string;
  kind?: SourceType;
  author?: string;
  edition?: string;
  locator?: string;
  url?: string;
  accessedAt?: string;
}
```

`UserSourceRef.accessedAt` 若存在，必须是用户本地日历的有效 `YYYY-MM-DD` 日期；备份导入会拒绝格式正确但实际不存在的日期（例如 `2026-02-30`）。

来源编辑器还提供一个账户级“来源模板”：复制时将单条已归一化的 `UserSourceRef` 与复制时间通过 `/api/data?table=sourceTemplates` 写入 PostgreSQL，粘贴时按版本、字段白名单、HTTP(S) 链接和本地日期规则重新解析后再填入当前笔记。模板不进入 AI 发送范围；解析失败只禁用粘贴，不影响现有笔记。设置页执行“清空账户数据”时会同步移除该模板并在确认摘要中提示其存在。

### 6.2 作答历史

```ts
type RecallGrade = "forgot" | "hard" | "remembered" | "mastered";

interface ReviewAttempt {
  id: string;
  cardId: string;
  exerciseVersion: number;
  targetType?: "trigram" | "concept" | "hexagram" | "five-element";
  promptSnapshot: string;
  answerSnapshot: string;
  objectiveCorrect?: boolean;
  hintUsed?: boolean;
  selfExplanation?: string;
  recallGrade: RecallGrade;
  responseTimeMs?: number;
  reviewedAt: string;
  localDate: string;
}
```

保留题目与答案快照，是为了防止日后修改题目后无法解释历史结果。

`responseTimeMs` 为可选的本地学习遥测，表示从题目展示到提交答案的整数毫秒数；写入、迁移和备份导入均限制在 `0–86,400,000` 毫秒（24 小时）内。当前仅用于复习会话的本地预计剩余时间（使用有效历史样本的中位数，忽略超过 5 分钟的后台停留样本）；不参与对错判定、复习评价或掌握度计算，缺失时保持兼容，不向远端发送。

`selfExplanation` 为可选的学习者自述快照，由复习评价前填写“用自己的话复述”产生；写入前会去除首尾空白，空白值不落库，最长 2,000 个字符。它只保存在当前浏览器的 `ReviewAttempt`、备份和迁移边界中，并在本地混淆点回顾显示；默认不进入 AI 授权输入、不上传远端，也不改变对错判定或调度结果。

### 6.3 复习卡状态

```ts
interface ReviewCardState {
  cardId: string;
```

六十四卦是工具化内容索引，不设置或展示“未开始、学习中、已掌握”等学习阶段。索引仅异步读取账户收藏；收藏读取失败不能阻断卦库浏览。测试学堂和复习系统仍可记录对应题目的作答与调度数据，但这些记录不再被解释为整卦的学习阶段。

干支关系记录由严格 schema 校验关系类型、双方 ID、标题、可选结果五行、解释、来源和状态，并检查五合、六合、六冲的数量、配对唯一性和标题与配对一致；它只服务于分层记忆，不输出个人判断。

`masteryScore` 不是事实来源；事实来源始终是 `ReviewAttempt`。如算法调整，应能从作答历史重算掌握度。

## 7. 复习算法规格

### 7.1 间隔配置

```ts
const REVIEW_INTERVAL_DAYS = [1, 3, 7, 15, 30, 60] as const;
```

### 7.2 状态变化

| 评价       | stepIndex 变化           | 下次到期         |
| ---------- | ------------------------ | ---------------- |
| forgot     | `max(0, current - 1)`    | 明天             |
| hard       | 不变                     | 2 天后           |
| remembered | `min(last, current + 1)` | 新 step 对应间隔 |
| mastered   | `min(last, current + 2)` | 新 step 对应间隔 |

补充规则：

- 新卡初始 `stepIndex = 0`；
- 即时练习通过后，首次间隔复习为次日；
- `forgot` 增加 `lapseCount`，连续两次 `forgot` 后 `isWeak = true`；
- 连续两次 `remembered/mastered` 后解除薄弱标记；
- 同一天重复复习保留每次 attempt，但只有最后一次有效评价推动下一到期日；
- 日期计算使用日历天，不使用固定 24 小时毫秒数相加。
- 运行时边界仍需校验评价值只能是 `forgot`、`hard`、`remembered` 或 `mastered`；类型擦除、外部调用或损坏数据不得静默落入某个评价分支，未知值应以明确错误阻止写入。复习写入还要确认题目 ID、题型、目标、提示、选项和答案与当前不可变练习定义一致，并校验对错/提示布尔值、复习模式、带时区时间戳和真实本地日期。
- 调度器在进行阶梯算术前还必须校验当前卡片状态：`stepIndex` 必须是 `[0, REVIEW_INTERVAL_DAYS.length)` 内的安全整数，遗忘/连续通过/连续遗忘计数必须是非负安全整数，`isWeak` 必须是布尔值，`dueDate` 必须是真实本地日期；绕过迁移层直接传入损坏状态时应抛出明确错误。复习队列、首页到期摘要和“立即再练”复用同一非抛出校验并提前隔离坏卡，不能等到提交时才失败。
- 所有学习读模型也必须沿用同一状态边界：今日总结、统计页的累计/长期指标、最近学习位置、薄弱点和本地混淆点在存在对应复习卡状态时，只接受当前算法可解释且结构有效的状态；损坏或不支持的状态不得污染计数、排序、错误聚合或详情入口。没有状态的历史 fixture 仅作为兼容性输入，不得被新写入路径产生。
- 复习结果的 repository 入口复用题目快照与提交字段校验；不符合当前内容定义的输入不得生成复习卡状态或作答历史，避免历史统计被伪造快照污染。
- 备份导入对当前 `exerciseVersion` 的已知复习题继续核对 `promptSnapshot` 与 `answerSnapshot`；缺少版本号的旧备份保留兼容性并按不透明历史快照处理。
- AI 草稿审阅状态与事件采用严格字段白名单；未知状态字段、事件字段或缺失事件载荷必须在运行时拒绝，不能静默丢弃。
- AI 草稿审阅快照还需满足状态—载荷一致性：`pending` 状态的编辑文本必须等于原始草稿，只有进入 `editing` 后才能改变文本。
- 勘误的原子状态更新也必须在 updater 返回值上重新执行完整领域校验，不能因“读—改—写”路径绕过状态历史、时间和字段边界。

### 7.3 可替换性

调度器输入输出必须是纯数据：

```ts
scheduleNext(currentState, grade, localDate, config) => nextState
```

未来更换为其他间隔算法时：

- 不修改历史作答；
- 调度器记录 `algorithmVersion`；
- 可以选择仅影响后续作答，或经用户确认后重算全部卡片。

### 7.4 学习指标重算

统计页只读取 `ReviewAttempt` 和当前 `ReviewCardState`，并在内存中重算，不把汇总数字作为新的事实来源。当前实现提供：

- 7 日学习留存：从最早有效作答日开始，观察第 7 个日历日是否仍有作答；观察窗口未结束时返回 `null`；
- 7 日后记忆率：按卡片分组，统计相邻作答相隔至少 7 个本地日历日时，后一次评价为“记得/熟练”的比例；无符合记录时返回 `null`。
- 到期卡完成率：将当天以间隔模式完成的卡片与仍然到期的卡片组成当天到期集合，计算已完成卡片比例；没有到期卡时返回 `null`。
- 推演独立完成率：只统计 `targetType=hexagram` 的作答，`hintUsed` 不为 `true` 才计为独立完成；旧记录缺少题目类型时不纳入该指标。
- 14 日薄弱点改善率：按卡片识别连续两次“忘记”形成的薄弱事件，统计事件后 14 个日历日内连续两次非“忘记”评价的比例；即时练习不参与，观察窗口不足时返回 `null`。

指标函数位于 `core/review/stats.ts`，统一使用本地日期字符串和纯公历日序整数计算日历日差，不依赖时区或固定 24 小时毫秒数推导；界面以“—”呈现 `null`，避免把尚未观察到的数据误报为 0%。

### 8.1 建议表

| 表                 | 主键      | 关键索引                                                |
| ------------------ | --------- | ------------------------------------------------------- |
| notes              | id        | targetId, updatedAt, deletedAt                          |
| reviewAttempts     | id        | cardId, reviewedAt, localDate                           |
| reviewCardStates   | cardId    | dueDate, isWeak, targetId                               |
| conceptProgress    | conceptId | status, updatedAt                                       |

| labSnapshots       | id        | createdAt, updatedAt, baseHexagramId, changedHexagramId |
| preferences        | key       | 无                                                      |
| errata             | id        | targetType, targetId, status, updatedAt, createdAt      |
| compassRecords     | id        | createdAt, updatedAt, degrees, directionId              |
| compassCorrections | id        | createdAt, updatedAt, offsetDegrees                     |
| recoverySnapshots  | id        | createdAt                                               |
| metadata           | key       | 无                                                      |

内容勘误记录的 `history` 为追加型状态历史；新建记录写入首个 `open` 事件，切换“已处理/待处理”时追加事件，不覆盖已有记录。旧版本记录在 v8 迁移时补齐首个 `open` 状态事件、按顶层字段白名单清理未知字段，并把倒序时间钳制为单调序列；当迁移追加状态事件时，其时间不得早于已有最后事件。导入旧备份也会执行同一归一化。普通 repository 新建写入会再次校验目标、描述、内容版本、时间戳和历史顺序，要求首个状态为 `open` 且末项与当前状态一致；历史为空、状态矛盾、时间倒序或顶层未知字段会明确拒绝。状态历史条目还拒绝未声明字段，避免本地写入契约漂移。

### 8.2 数据库版本

- 版本从 1 开始递增；
- 当前服务端迁移版本为 v4：v1 建立账户、会话和 `user_records`，v2 增加登录时间索引，v3 建立笔记、收藏、复习、进度、偏好、推演、罗盘、勘误和 AI 审计表，v4 增加管理员与禁用状态并将最早账户设为管理员；后续只追加版本，不修改已执行迁移。
- 每个版本只能向前迁移，发布后不得修改旧迁移逻辑；
- 迁移前写入最近一次导出提示或创建可恢复快照；导入合并前在同一事务内写入本地恢复快照，成功后可由用户撤销最近一次导入；该快照不进入正常导出文件；
- 迁移函数必须有从上一版本样例数据升级的自动化测试；
- 应用启动时迁移失败要进入只读错误页，不能继续写入半迁移数据库。

迁移时间顺序约束：对带有 `createdAt`/`updatedAt` 的用户记录，启动归一化在修复 ISO 格式后还必须保证 `updatedAt >= createdAt`；笔记的可选 `deletedAt` 若早于 `createdAt` 则移除。该修复只作用于历史坏数据，不改变合法记录的原始时间。

数据变更通知由 `db/events.ts` 统一发出：当前标签页使用自定义事件即时刷新，同源其他标签页通过 `BroadcastChannel` 接收。通知只触发重新读取服务端 API，不把任何记录内容写入跨标签页消息。

数据库访问边界：页面组件只能调用 `db/repository.ts` 和 `db/backup-repository.ts` 暴露的领域函数，不直接拼装 API 请求或持有浏览器存储实例。单表查询/写入、笔记原子 upsert、课程进度写入以及备份导入/撤销/清空均由 repository 统一管理；服务端 `/api/data` 按会话用户隔离记录，新增表或迁移逻辑时，应优先扩展服务端迁移和 repository 领域函数并补充测试。

课程进度写入边界：课程里程碑分数必须是有限数字；目标知识点必须存在已配置练习，否则拒绝写入，避免产生 `NaN` 掌握度或孤立进度记录。`now` 必须是有效带时区 ISO 时间戳，种卡使用的 `today` 必须是真实本地日历日期；无效时间不得进入掌握度或复习卡写入。

笔记写入边界：正文、标签、来源引用、内容目标、创建/更新时间和软删除时间由 `normalizeNoteForWrite` 统一校验；内容型目标必须存在于当前目录，会话笔记允许独立会话 ID；来源链接仅接受带主机的 HTTP(S)，访问日期必须是真实本地日期，原子更新和新建路径不得绕过该校验。

笔记聚合搜索由 `core/notes/search.ts` 生成统一可搜索投影，覆盖正文、标题、目标上下文、标签以及来源名称、类型（含中英文显示词；旧来源缺少类型时按个人来源处理）、作者、版本、定位、链接和访问日期，避免来源元数据只能显示而无法检索。
原子更新还必须绑定调用方传入的主键：updater 返回记录的 `id` 若与目标 ID 不一致，应明确失败，不能写入另一条记录。
笔记时间线必须单调：`updatedAt` 和（如有）`deletedAt` 不得早于 `createdAt`；备份导入需执行同一检查。

## 9. 导入导出协议

```ts
interface ExportEnvelope {
  format: "yijing-local-backup";
  schemaVersion: number;
  appVersion: string;
  contentVersion: string;
  exportedAt: string;
  data: {
    notes: UserNote[];
    reviewAttempts: ReviewAttempt[];
    reviewCardStates: ReviewCardState[];
    conceptProgress: ConceptProgress[];
    favorites: unknown[];
    preferences: PreferenceRecord[];
    labSnapshots: LabSnapshotRecord[];
    errata: ContentErratumRecord[];
    compassRecords: CompassRecord[];
    compassCorrections: CompassCorrectionRecord[];
  };
  checksum?: string;
}
```

导入流程：

```text
读取文件 → JSON 解析 → schema 校验 → 版本兼容检查 → 统计预览
        → 用户确认 → 在单一事务中合并 → 完整性检查 → 显示结果
```

导出流程同样先读取各用户表并形成待导出快照，展示数据范围和数量；用户确认后直接导出该快照，保证预览与文件一致；内置经典正文不重复写入备份。

合并规则：

- 相同 ID、内容相同：跳过；
- 相同 ID、内容不同：默认保留 `updatedAt` 较新的版本，并在结果中计入冲突；
- 作答历史为追加型记录，同 ID 冲突视为备份异常；
- 导入前后的记录数和关键引用必须校验；
- 未来跨设备同步不能直接复用“更新时间覆盖”作为最终冲突策略。

当前实现：备份协议校验器位于 `core/data/backup.ts`，会校验各表必要字段、信封中存在的应用/内容版本和带时区的 ISO 8601 导出时间、用户记录时间戳、来源链接必须为带主机的 HTTP(S)、日期/枚举/范围、表内主键唯一性以及跨表对象引用；repository 从服务端 API 读取账户快照，导入前保存 `recoverySnapshots`，确认后合并写入并重算掌握度。导入校验失败不会提交；AI 偏好仍按授权范围和用途白名单校验；客户端不创建浏览器数据库，迁移由 Compose 启动阶段的 PostgreSQL DDL 负责。

补充（2026-08-29）：备份信封、各数据表记录及嵌套来源/勘误历史均采用严格字段契约；解析阶段拒绝未声明字段，同时保留已声明的 `algorithmVersion`、可选导出元数据和未来算法版本兼容策略。导入归一化只复制协议规定的数据表和嵌套集合，不把 UI 预览元数据带入合并事务，并以独立快照承载待导入数据；迁移提醒的本地序列化对象也拒绝未声明字段。已知复习卡会继续校验目标定义一致性，未知卡 ID 不因本版本练习目录变化而被误拒绝。导出文件现在生成可选的非加密校验和，导入若提供该字段则验证数据是否在保存或传输中发生意外变化；没有校验和的历史文件仍可导入。

补充（2026-08-30）：备份导入笔记在归一化阶段复用 `normalizeNoteForWrite`，统一清理标签与来源元数据空白，并拒绝空白来源名称；因此备份入口与普通笔记写入共享同一内容目标、来源链接和字段边界。

复习卡引用补充：对本版本已知的复习卡 ID，备份校验器还会将 `targetType`/`targetId` 与不可变练习定义交叉校验，防止合法对象被替换为另一题；未来未知复习卡 ID 仍按不透明标识保留兼容性。

## 10. UI 与视觉技术约束

### 10.1 设计令牌

首版先定义语义变量，不在组件中散落固定颜色：

```css
--color-bg;
--color-surface;
--color-text;
--color-muted;
--color-border;
--color-accent;
--color-yin;
--color-yang;
--color-moving;
--color-success;
--color-warning;
--color-danger;
```

阴阳颜色不等于“好/坏”；颜色之外必须有线型或文字辅助。

### 10.2 卦爻组件

建议只保留一个领域组件族：

- `LineGlyph`：单爻；
- `TrigramGlyph`：三爻；
- `HexagramGlyph`：六爻；
- `InteractiveHexagram`：可点击和带动爻状态的六爻。

所有尺寸由属性控制，页面不能重复手动画线，以免方向和间距不一致。

### 10.3 中文正文尺寸

课程正文、页面导语、工具说明、练习题干、反馈解释和个人笔记编辑/预览等阅读内容默认使用不小于 `16px` 的字号；来源编号、时间、状态标签等辅助元数据可以使用较小字号，但不能承担正文语义。大字号偏好在上述正文区域统一提升到 `18px`。

### 10.4 无障碍语义

- 可点击爻使用 `button`，其名称类似“第三爻，阴爻，点击变为阳爻”；
- 卦符旁保留文字卦名；
- 动爻使用颜色、标记和辅助文字三重表达；
- 焦点顺序按页面阅读顺序；
- 动画遵从 `prefers-reduced-motion`。

### 12.2 干支与历法

边界清单在输入审阅阶段分别展示换年、换月、换日、子时、二十四节气和真太阳时六项状态；在规则复核前均不得推导干支结果。

历法算法单独作为 `core/calendar` 领域，不与 UI 混写；每个结果必须包含时区、历法规则版本和输入时间，测试采用权威样例集。换年、换月、换日和子时边界遵循 [ADR-0002](./adr/0002-历法与干支时间边界.md)，在规则复核前不实现自动排盘。`assertCalendarInput` 与 `assertCalendarRuleSet` 会拒绝未声明字段，并校验输入时间、IANA 时区、规则版本、边界枚举、规则来源 ID 和权威样例 ID；规则集版本 ID 与所有证据 ID 必须是已修剪的非空字符串；只有非空来源/样例且边界完整的规则集才能标记为 `accepted`，`buildPendingCalendarReading` 也拒绝已接受规则集，防止状态语义错位。`describeCalendarBoundaries` 为输入审阅页提供逐项边界状态清单，明确区分 `pending` 与 `configured`，不参与任何日期或干支推导。`buildPendingCalendarReading` 会先检查输入 `ruleVersion` 与规则集 ID 一致，防止跨版本误标；`interpretCalendarTime` 负责把显式偏移或 IANA 时区本地时间规范化为可核对的公历展示；它缓存每个 IANA 时区的格式化器，并在宽窗口内按 6 小时采样偏移后逐一验证候选，夏令时重复/不存在的本地时间会返回显式状态并拒绝静默选择 UTC 瞬间。待确认阅读的解释会按“显式偏移转换”或“本地墙上时间匹配”分别说明展示语义，避免把两种时区输入混为一谈。

权威样例登记契约位于 `core/calendar/evidence.ts`：每个样例必须带修剪且唯一的 ID、规则版本、边界类型、带时区输入、期望的公历/农历/节气/干支结构、来源 ID 和 `pending`/`verified` 状态；样例输入的规则版本必须与样例版本一致，期望干支层必须与字段键一致。`assertCalendarEvidenceSet` 还会在规则集进入 `accepted` 前检查其样例已登记、版本一致、来源属于规则集、样例已核验且覆盖换年/换月/换日/子时/时区/节气六类边界；`inspectCalendarEvidenceCoverage` 可为仍在审核中的候选规则返回逐边界缺口报告。`content/calendar-evidence.ts` 在使用全局来源登记表时，进一步要求 `accepted` 规则及其样例/节气来源均为已核验状态；`core/calendar/evidence-payload.ts` 提供裸数组或 `{ ruleSet, samples }` envelope 的严格解析与双视图覆盖预览；`/settings/content` 的只读校验器可粘贴或选择外部 JSON，并额外检查来源是否存在于全局登记表，不会写入内置内容。该契约只验证内容交接数据，不凭空提供历法事实或计算结果。

M2 的河图、洛书和九宫静态记录由严格 schema 校验 ID、数字、行列、方位、卦关联、五行、记忆提示、来源和状态；构建门禁要求河图五组、洛书九格和九宫九项的数量、数字/宫位唯一性及洛书 1～9 总和为 45。该工具只用于结构化记忆，不延伸到个人判断或自动排盘。

罗盘静态数据同样采用严格 schema：八方方向表要求固定八项、ID/标签唯一、中心角度位于 `[0,360)` 且按 45° 顺序排列，并交叉校验中心角度与方向 ID 的映射；盘层注册表要求 ID 唯一、恰好一个已启用层，已启用层必须已复核且有来源，禁用层必须处于待确认状态并说明原因。当前只校验通用八方与待确认二十四山占位层，不扩展二十四山名称、角度或流派判断。手工坐向写入在 UI 与 repository 两层统一归一化角度，并在 repository 边界拒绝角度与方向快照不一致或不受支持的盘层/规则版本，避免未来新增入口绕过数据不变量。

### 12.3 罗盘

罗盘分两层建设：

1. 纯软件盘层：用户拖动角度，先学习基础八方，再按来源扩展二十四山和盘层；
2. 真实传感器：读取设备方向、权限状态和校准信息。

当前已实现的首个纯软件层只包含通用 360° 八方几何映射，计算位于 `core/compass`，标签和来源位于 `content/compass.ts`；隐藏标签和方位测验属于学习交互，不改变计算规则。二十四山和流派盘层仍需独立 ADR、来源及真机验收。M3-B02 的方向事件适配位于 `core/compass/sensor.ts`：优先使用 WebKit 罗盘字段，其他平台只把绝对 alpha 转为带“精度未知”标记的估算；M3-B03 增加最近最多 8 个样本的环形平均和最大角距离稳定性提示，窗口大小、最小样本数和阈值遇到非有限值时回退到 8/4/5° 安全默认值；UI 负责用户手势授权、事件生命周期和手动回退，读数与稳定性状态不写入 `CompassRecord`。

真实传感器读数必须持续显示精度、磁干扰和校准限制；当前已实现稳定性提示、手动偏差历史和平台诊断，真机平台矩阵仍是 M3-B05 的发布门槛。手动偏差记录在 UI 与 repository 两层均通过同一归一化函数限制在 `-180°～+180°`，避免绕过表单的写入入口持久化不可解释修正值。

### 12.4 AI 辅学

AI 只能通过显式接口读取用户选定的笔记和学习记录。输出需要标记“AI 辅助”，默认功能顺序为：

当前已实现 M4-001～M4-005 的本地授权、发送预览、草稿输出、安全评测和审阅工作流，并完成 M4-006/M4-007 的本地策略基础与供应商适配契约：`core/ai/consent.ts` 定义范围、用途、允许字段、排除字段、契约版本和一次性传输策略；运行时预览拒绝顶层未知字段、未知用途、空授权范围、篡改字段和错误传输/留存策略，即使绕过 UI 或 TypeScript 也不能生成无范围有效请求；`core/ai/output.ts` 定义草稿类型、输入范围、来源引用和固定免责声明，供应商输出必须拒绝未知/重复输入范围、未修剪来源 ID 及非字符串来源定位；`content/ai-evaluation.ts` 提供确定性预测、混淆流派和误引原文案例；`core/ai/evaluation.ts` 执行草稿安全评估；`core/ai/review.ts` 约束待审阅、编辑、接受、拒绝和重置状态，未知事件类型、损坏状态快照与非字符串编辑文本均在运行时拒绝；`core/ai/service-policy.ts` 定义远端删除确认、离线/超时/服务不可用/请求体超限/无法序列化回退策略；`core/ai/provider.ts` 约束请求对象、用户确认、授权预览校验、字段白名单、JSON 可序列化检查、请求体大小（默认 50,000 字符、绝对上限 100,000）、超时上限（60 秒）、校验后 JSON 快照、输出校验和安全评估的供应商调用边界，并在序列化后再次拒绝空值、数组、丢失原字段或新增未授权顶层字段；`/settings/ai` 只保存偏好并生成本地预览，不读取整库、不联网。远端模型接入前仍需完成真实用户确认、远端删除执行和服务适配，详见 ADR-0008。
其中 `AI_EVALUATION_CASES` 通过严格 schema 校验风险类型、输出类型、提示词、必含/禁用标记和来源数量，构建门禁要求三类风险各有覆盖、案例 ID 唯一且标记不自相矛盾；`assertAiDraftOutput` 还会拒绝草稿顶层与来源引用对象的未知字段，避免供应商响应携带未声明数据；这些门禁只保证契约与评测样例完整，不代表已接入真实模型。

内容治理设置页位于 `/settings/content`，只读取内置静态内容并集中展示知识点、卦辞、爻辞和来源的复核数量、发布门禁与收录策略；同时读取本地 `errata` 表汇总待处理/已处理勘误，并展示历法规则集与六类边界样例覆盖状态。页面可导出只含复核元数据的 JSON 交接包，当前 `reportVersion: 2`，保留来源的作者、版本、出版信息、定位、访问日期和版权说明，并附带历法规则版本、来源/权威样例 ID、逐边界覆盖和缺口统计；明确 `includesCanonicalText: false`，不携带经典原文、编辑 Markdown 或未经确认的历法事实，便于内容负责人逐条核对。交接包在序列化边界执行严格 schema、枚举、清单 ID 唯一性、当前知识点/卦辞/爻辞目录 ID 与目标映射一致性、计数、发布门禁一致性、来源引用完整性和历法六类边界覆盖统计校验，拒绝未知字段、伪造“已可发布”状态、不合法来源链接、无效访问日期、未知/重复/空来源引用、条目替换或 accepted 规则的不完整证据。它不提供未经授权的原文编辑，也不改变 `pending` 内容状态。

1. 根据已校对内容生成练习草稿；
2. 识别用户常见混淆点；
3. 引导用户用自己的话解释；
4. 对比用户笔记与已校对知识；
5. 最后才考虑开放式卦象解释。

AI 不得覆盖经典原文、程序计算结果或用户原笔记。

## 13. 架构决策流程

当需要改变以下事项时，在 `docs/adr/` 新增一份短 ADR：

- 框架或数据库；
- 卦象编码方向；
- 关系卦计算定义；
- 内容来源版本；
- 复习算法；
- 账户优先策略；
- 云同步冲突规则。

每份 ADR 至少写清：背景、决策、替代方案、影响、迁移方式和日期。
