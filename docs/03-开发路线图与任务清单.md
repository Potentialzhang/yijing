## 2. 估算与状态规则

### 2.1 工作量

| 标记 | 理想开发工作量 | 说明                       |
| ---- | -------------: | -------------------------- |
| XS   |     0.5 天以内 | 小配置、小组件、小数据修正 |
| S    |        约 1 天 | 单一功能，有清晰测试边界   |
| M    |        2～3 天 | 跨组件或含数据持久化       |
| L    |        4～5 天 | 一条完整用户流程或复杂交互 |
| XL   |       需要拆分 | 不允许直接进入迭代         |

估算不包含等待内容复核的时间，也不是交付承诺。若任务实际超过 L，开发前必须再拆分。

### 2.2 任务状态

- `TODO`：范围和验收已明确，尚未开始；
- `DOING`：正在开发，同一时间最多一个主任务；
- `VERIFY`：实现完成，等待自动化或人工验收；
- `DONE`：验收标准全部满足；
- `BLOCKED`：存在明确外部阻塞，记录原因和解除条件。

### 2.3 优先级

- P0：MVP 发布阻塞；
- P1：首个增强版本；
- P2：后续领域扩展；
- P3：想法池，不安排开发时间。

## 16. Definition of Ready

一个任务进入开发前必须满足：

- 目标用户行为明确；
- P0/P1 优先级明确；
- 输入、输出、空状态和错误状态明确；
- 数据来源或测试样例可获得；
- 依赖任务已完成；
- 验收标准可以由测试或人工步骤验证；
- 任务工作量不超过 L；
- 涉及规则差异时已有 ADR 或明确版本标签。

## 17. Definition of Done

一个功能只有满足以下条件才能标记 DONE：

- 实现符合 PRD，未静默扩大范围；
- 类型检查、静态检查、相关测试通过；
- 核心正常、空、错误和加载状态可用；
- 手机和桌面布局已检查；
- 键盘与基本无障碍语义已检查；
- 数据写入、刷新恢复和失败路径已检查；
- 新数据结构有 schema 与迁移；
- 新规则或内容有来源/版本；
- 文档和任务状态已更新；
- 没有留下未登记的高风险 TODO。
