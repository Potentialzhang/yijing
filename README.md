## 开发

```bash
npm install
npm run dev
```

质量检查：

```bash
npm run verify
npm run verify:content
npm run verify:release
npm run typecheck
npm test
npm run lint
npm run test:a11y
npm run test:perf
npm run test:responsive
npm run test:mobile
npm run build && npm run test:mobile:prod
npm run test:e2e
npm run build
npm run test:smoke
npm run test:e2e:prod
# 本地开发测试环境（持续运行，另开终端执行 E2E）
npm run local:test
# Docker 构建并一键部署
npm run deploy
# 如需隔离浏览器并降低本机并发压力：
npm run test:e2e:prod:chromium
npm run test:e2e:prod:webkit
npm run test:e2e:prod:firefox
```

`npm run test:smoke` 会启动已构建的生产服务，检查关键页面、Manifest 和 Service Worker；也可以通过 `SMOKE_BASE_URL=https://your-host.example npm run test:smoke` 检查已部署环境。
`npm run verify:content` 只运行内容结构与复核交接门禁；`npm run verify:release` 会先运行基础质量门禁，再单独输出内容门禁，随后串行执行无障碍、响应式、性能、Chromium/WebKit 生产 E2E 与移动端生产模拟；它不隐藏 Firefox 阻塞，Firefox 仍需单独在稳定版浏览器或 CI 环境运行。
`npm run test:e2e:prod` 使用已构建的生产服务运行 E2E；若要指定用例，可在命令后追加 Playwright 参数。Chromium 单浏览器入口默认使用 2 worker，WebKit 生产入口默认使用 1 worker 以避免本机进程模型下的导航/IndexedDB 资源争用；需要诊断并行差异时可显式追加 `--workers=2`。

本地开发测试环境可运行 `npm run local:test`，命令会等待 `/api/health` 就绪并持续提供 `http://127.0.0.1:3000`；Docker 一键部署运行 `npm run deploy`，也可使用 `docker compose up -d --build`，完整说明见 [`docs/06-本地测试与Docker部署.md`](./docs/06-本地测试与Docker部署.md)。

仓库内的 `.github/workflows/quality.yml` 会在 GitHub Actions 中执行 lint、类型检查、单元测试、生产构建、Chromium/WebKit/Firefox 生产 E2E、移动端触控模拟和冒烟测试；Firefox 生产验收也可在本地运行 `npm run test:e2e:prod:firefox`（需先安装对应 Playwright 浏览器）。

Firefox 验收默认使用 Playwright 管理的浏览器；启动预检默认 15 秒、测试总预算 120 秒，均会主动终止卡住的进程；两个 Firefox 入口会跟随自定义启动预算同步父进程等待时间，并对非法测试预算回退默认值；CI 或本机存在其他稳定 Firefox 时，可通过
`PLAYWRIGHT_FIREFOX_EXECUTABLE_PATH=/path/to/firefox npm run test:e2e:firefox` 指定可执行文件，也可用 `FIREFOX_LAUNCH_TIMEOUT_MS` / `FIREFOX_TEST_TIMEOUT_MS` 调整启动和测试超时。

产品、数据规范和开发任务见 [`docs/README.md`](./docs/README.md)。

## 数据约定

核心卦象数组统一按“从下往上”存储：阳爻为 `1`，阴爻为 `0`。显示层可以改变绘制顺序，但不能改变领域数据顺序。

当前内容中的经典原文和释义仍处于待来源校对状态，页面会明确标注，不以临时生成文本冒充原典。
