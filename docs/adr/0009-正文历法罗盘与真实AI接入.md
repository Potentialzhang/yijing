# ADR-0009：正文、历法、二十四山与真实 AI 接入

日期：2026-09-05。状态：个人学习应用实现已采用；外部专业审校与真实模型账户联调另列验收，不冒充已经完成。

本决策承接用户“完成四类未完成功能”的请求，替代 ADR-0001、0002、0008 中仅占位、未计算、未接模型的阶段限制；保留来源分层、规则可追溯、逐次授权和失败不伪造结果的约束。

## 正文与释义

- 采用公版《周易》古文，不复制现代译注。底本为 [Kanripo KR1a0001 固定修订](https://github.com/kanripo/KR1a0001/tree/8284adbf9e3435d713180e24f05bf75f8b7d1d96)，保留异体字与原有标点。
- `scripts/import-zhouyi.mjs` 可复现导入；`content/zhouyi-canonical.json` 留存每卦原始文件 URL、SHA-256 与版本。只移除页码、分行等版面控制符。
- 64 条卦辞与 384 条爻辞逐条对应文王序与自下而上的爻位；用九、用六另存另展，不计入六爻。
- `content/zhouyi-editorial.ts` 是项目自编学习释义，每卦一段及每爻一段。原文与释义分区，不宣称是逐字译文、传统定论或唯一解释。
- 内部 `verified`／页面“已校对”表示本轮底本抽取、条数与爻位的程序核验；不表示专业人士逐条签字审定。古籍逐字比勘与释义专业审校继续保留人工任务。

## 历法计算

- 固定 `lunar-typescript@1.8.6`，通过 [维护者算法文档](https://github.com/6tail/lunar-typescript) 明确方法来源。支持输入当地公历 1901～2099 年，节气邻年计算限 1900～2100。
- 两个明确版本：`calendar-lichun-jie-midnight-v1`（默认零点换日）、`calendar-lichun-jie-zi-v1`（当地 23 点换日）。均按立春瞬间换年、十二个“节”换月，中气不换月。
- 先解析输入到 UTC 瞬间。年／月柱使用同一瞬间对应的中国标准时间判断节令，日／时柱用用户 IANA 时区的当地标准钟表时间。时干由所选换日规则的日干推算，不混用库的子初习惯。
- 农历标签按中国标准时间编算，并与海外当地日期区分。不做真太阳时、磁偏角或命运预测；不将香港天文台按农历正月初一的年干支标签冒充立春规则证据。
- 节气按 UTC 瞬间保存，在输入时区展示到分钟。算法秒数不代表天文台认证的秒级精度；临界秒附近有误差风险。
- 香港天文台 [2026 年对照表](https://www.hko.gov.hk/en/gts/time/calendar/text/files/T2026e.txt) 独立核对春节／农历日期和立春日期，记录于 `calendar-calculation-evidence.ts`。其余边界测试验证实现一致性，不宣称所有年份所有边界都有独立权威认证。
- 原 `calendar-draft-1` 与六类证据审阅工具继续保留为旧规则审计入口；不能把旧草案的未完成证据状态等同于新计算器不可用。`accepted` 表示本应用采用明确约定，不代表旧证据模板已获人工批准。

## 二十四山

采用地盘正针，子山中心 0°，顺时针每山 15°，范围中心 ±7.5°，左闭右开；向首取输入角度、坐山取 +180°。盘面与按钮共用 `mountainAt`，不另写一套边界逻辑。正五行由既有干支／八卦属性归类，不混入三元龙阴阳、兼向、天盘人盘或吉凶判断。方位事实登记 [罗庚二十四山表](https://zh.wikipedia.org/wiki/羅庚)。

沿用原坐向记录保存原始角度与八方兼容元数据；记录列表另按当前正针规则换算二十四山坐向，不把旧记录的盘层伪改为新盘层。传感器仍须用户主动开启，真实设备误差另行验收。

## 真实 AI 与隐私

- 服务端 `POST /api/ai/study` 调用 Responses API，采用 [官方结构化输出协议](https://developers.openai.com/api/docs/guides/structured-outputs)，服务器独立校验输入与输出。不采用“请求失败就返回演示内容”的回退。
- 必须配置服务器 `OPENAI_API_KEY` 和 `OPENAI_MODEL`，不使用 `NEXT_PUBLIC_`，Docker 构建排除 `.env*`（保留示例）。可配置兼容 Responses 与 JSON Schema 的 HTTPS base URL；不是任意 Chat Completions 接口都兼容。
- 授权范围之后还需选择具体材料、预览实际快照、逐次确认。最多 4 项知识、10 篇笔记、最近 30 条中选定的作答；快照 50000 字符，HTTP 请求体 180000 字节。原文知识在服务端重建核验以拒绝伪造。
- 个性化出题返回三道选择题及反馈；笔记整理、观点对比、错题分析、启发式追问、卦象讨论返回独立草稿。只引用选定材料 ID；引用合法不等于内容绝对正确，接受前仍需人工审阅。
- `store:false`、无远端会话历史；不等于供应商零留存，供应商滥用监测和账户数据政策仍适用。撤销阻止新请求并取消/丢弃未完成输出，不承诺撤回已到达供应商的数据。
- 提供超时／取消／离线／配额／凭据／输出无效提示；无自动重试。服务端进程限制每分钟 10 次、同时 2 次。Origin 检查是跨站防护，不是身份认证；这是个人环境实现，公网开放前必须增加认证、按用户限额与预算控制。
- 草稿接受后作为 `session:ai-draft-UUID` 新笔记保存，支持笔记库回看、继续编辑、删除及现有备份；不覆盖输入原笔记。生成练习暂不自动写入正式 SRS 卡库或掌握度，避免未审校题目污染指标。
- Service Worker v61 不处理 `/api/`，只缓存静态页壳；AI 草稿内容不写入共享 HTTP 缓存。

## 验证边界

自动化分为原文完整性与计算边界单测、模拟上游 HTTP 的适配器／路由契约测试、浏览器交互测试。没有真实密钥时不能声称通过真实模型在线验收。真实凭据、供应商费用、人工审校、真机传感器与部署操作须使用交付文档中的后续清单。
