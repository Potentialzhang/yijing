# 易境正式数据库设计

数据库：PostgreSQL 16。所有个人数据以 `user_id` 隔离；客户端不再作为业务数据源，浏览器仅保存 HttpOnly 会话 Cookie。

```text
users ──< sessions
  │
  ├──< notes / favorites / review_attempts / review_card_states
  ├──< concept_progress / preferences / lab_snapshots
  ├──< compass_records / compass_corrections / content_errata
  ├──< ai_generations
  └──< user_records（统一账户记录 API 的 JSONB 写模型）
```

| 表 | 用途 | 主键/唯一约束 |
|---|---|---|
| `users` | 账户、密码哈希、显示名 | `id`、`email` 唯一 |
| `sessions` | HttpOnly 会话及过期时间 | `id`、`token_hash` 唯一 |
| `notes` | 卦、知识点、单爻、AI 草稿笔记 | `(user_id,target_type,target_id)` |
| `favorites` | 收藏 | `(user_id,target_type,target_id)` |
| `review_attempts` | 每次答题事实快照 | `id` |
| `review_card_states` | SRS 卡片调度状态 | `(user_id,card_id)` |
| `concept_progress` | 知识点掌握度 | `(user_id,concept_id)` |
| `preferences` | 主题、字号、AI 授权等 | `(user_id,key)` |
| `lab_snapshots` | 卦象实验室快照 | `id` |
| `compass_records` | 坐向观察记录 | `id` |
| `compass_corrections` | 传感器修正历史 | `id` |
| `content_errata` | 内容勘误与反馈 | `id` |
| `ai_generations` | AI 输出审计索引，不存 API 密钥 | `id` |
| `user_records` | 统一 API 的账户级 JSONB 写模型与扩展字段 | `(user_id,record_type,record_key)` |

JSONB 只用于标签、来源、扩展 payload 和 AI 来源编号；可查询的业务字段保持独立列。所有删除优先软删除或账户级级联删除；账户删除前必须二次确认并先导出数据。

## 启动与增量迁移

`schema_migrations` 记录已执行版本。容器启动顺序为：PostgreSQL 健康检查 → 应用执行 `scripts/migrate.mjs` → Next.js 服务启动。每个版本在事务中执行，重复启动幂等；后续只追加版本，不修改已执行迁移。

本项目当前为全新数据库，不迁移旧浏览器数据。业务 API 已接管全部个人数据（包括来源模板）；客户端不创建浏览器数据库，也不使用浏览器键值存储保存学习数据。公开内容仍可静态生成，个人数据接口必须有有效会话。
