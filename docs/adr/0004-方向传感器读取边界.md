# ADR-0004：方向传感器读取边界

> 状态：已接受（代码适配已完成，真机验收待完成）  
> 适用阶段：M3-B02  
> 日期：2026-08-26

## 背景

M3-B01 只探测浏览器能力，不注册方向事件。M3-B02 需要在用户明确点击后读取方向事件，同时保留手动学习盘，避免把平台相关的设备读数包装成确定的方位结论。

## 决策

1. 读取只能由用户点击“开始读取方向”触发；仅在安全上下文中运行。若平台提供授权接口，必须先完成授权；拒绝、异常或不支持时回到手动模式。
2. 优先使用 WebKit 提供的 `webkitCompassHeading` 作为设备罗盘读数；没有该字段时，只有 `absolute === true` 且 `alpha` 有效才生成“绝对 alpha 估算”。相对 alpha 不转换为方位。
3. 所有读数标记为 `accuracy: unknown`，页面持续显示磁干扰、姿态、平台实现和校准限制；当前不做磁偏角修正、校准算法、真北/磁北推断或现实决策建议。
4. 事件监听同时覆盖 `deviceorientation` 和 `deviceorientationabsolute`，停止、切换到测验、恢复记录和组件卸载时都必须清理监听。传感器读数不写入坐向记录；停止读取后恢复到开始读取前的手动角度。
5. 角度转换保持纯函数，位于 `core/compass/sensor.ts`；UI 只负责授权、事件生命周期和手动回退。平台差异、校准流程和精度展示不得隐藏在通用八方几何规则中。

## 依据与待验收项

- [W3C Device Orientation and Motion](https://www.w3.org/TR/orientation-event/)：方向事件、`absolute` 和 `alpha` 的平台接口约束；
- [Apple DeviceOrientationEvent](https://developer.apple.com/documentation/webkitjs/deviceorientationevent)：WebKit 方向事件和授权相关接口；
- 需要在真实 iOS Safari、Android Chrome 至少各两类设备上验证授权、事件字段、屏幕旋转、磁干扰和停止回退行为；在完成 M3-B03 校准提示前，不宣称测量精度。

## 未选择方案

- 不在页面加载时自动请求权限或读取事件；
- 不把相对 `alpha` 当作真实罗盘北向；
- 不将传感器结果自动保存、同步或用于二十四山、流派判断和排盘。
