## 已实现的使用流程

| 模块 | 入口 | 可执行操作 |
| --- | --- | --- |
| 周易正文 | `/hexagrams` → 任意卦 | 阅读 64 卦辞、384 爻辞和逐条学习释义；用九／用六单独查看；追溯固定底本与自编说明；继续逐爻笔记与勘误 |

## 开启真实模型

1. 在项目根目录创建仅保留于本机的 `.env.local`，按 `.env.example` 填写 `OPENAI_API_KEY`、`OPENAI_MODEL`。模型 ID 必须是你的账户可访问且支持 Responses 与结构化输出的模型；本项目不替你购买额度或预设未验证的可用模型。
2. 默认 `OPENAI_BASE_URL=https://api.openai.com/v1`。第三方需兼容 `/responses` 和严格 JSON Schema。反向代理时设置 `AI_ALLOWED_ORIGIN` 为实际浏览器 origin（协议、主机、端口一致，无末尾斜杠）。
3. 开发环境运行 `npm run dev`，已有服务需重启。生产运行 `npm run build`、`npm start`。Docker Compose 使用根目录 `.env` 注入运行时变量，改值后重建容器运行实例；不要将密钥提交代码、发到聊天或设置成 `NEXT_PUBLIC_` 变量。
4. 在 AI 设置页确认显示模型名称；开启授权并选定材料。先试一项知识的三题练习，再试一篇笔记整理和两篇笔记对比。只有点击“确认发送并生成”才调用模型，可能产生 API 费用。
5. 检查答案、解析、引用及隐私预览；接受一篇草稿，在笔记库回看并编辑；核对原笔记未被替换。最后撤销授权检查不再发送。

当前环境未提供真实模型密钥，因此实现和模拟 HTTP／浏览器链路可验收，但真实账户成功响应、延迟、费用与供应商兼容性尚不能标记通过。没有凭据时页面明确显示未配置并禁用发送，不伪造成功。

部署边界：现有服务用于个人／受信任网络。Origin 校验和进程限流不代替身份认证；**配置付费 API 后不要直接向不受信任公网开放**。应先增加登录与服务端身份校验、按用户配额和网关限流。

## 内容和算法约定

详见 [ADR-0009](./adr/0009-正文历法罗盘与真实AI接入.md)。古籍采用固定 Kanripo 修订，释义为项目自编，不是现代书籍译注。程序核验不等于专业逐字审定。计算支持 1901～2099 年，默认立春换年、十二节换月、当地零点换日，允许改为当地 23 点换日；农历按中国标准时间，无真太阳时。正针二十四山不是所有流派罗盘。AI 仅用于学习，输出必须回到来源核查。

| D：真实模型验收 | 所有者配置私有密钥和模型；执行三种主要任务及失败场景 | 至少各一次在线成功；记录延迟、费用、解析／来源质量；不记录密钥 | 待账户配置 |
| E：内容复核 | 逐卦逐爻比勘异体字、标点和释义；增加独立历法边界样例 | 人工勘误清单可追溯，秒级／流派争议明确标记 | 后续质量提升 |
| F：实际部署 | 真机方向、PWA 离线更新、HTTPS、备份恢复；公网前认证 | 真实设备误差说明、v60 缓存清理、密钥不入前端与镜像、权限限额有效 | 需部署环境验收 |
