# ADR-0001：学习型罗盘首个盘层范围

> 日期：2026-08-26
> 状态：已接受

## 背景

路线图要求先建设可解释的纯软件罗盘，再考虑二十四山和真实传感器。当前尚未完成流派、磁偏角、真北/磁北和二十四山来源复核，直接输出这些内容会把未确认规则伪装成确定结论。

## 决策

首个盘层只实现通用几何八方：0° 为北，角度顺时针增加；八个方向中心分别为 0°、45°、90°、135°、180°、225°、270°、315°；每个方向覆盖中心左右 22.5°。输入仅来自用户手动输入或滑块。

页面必须展示角度、命中的方向、分区范围和测量边界；明确不读取设备传感器、不包含二十四山、不包含磁偏角修正、不做流派判断或现实决策建议。

## 未采用方案

- 直接接入设备方向传感器：依赖 HTTPS、权限、平台差异和真机校准，留到 M3-B。
- 首次实现二十四山：需要流派 ADR、名称/角度/阴阳/五行来源和边界样例，留到 M3-A03。
- 将八方映射到完整风水盘：超出当前可验证范围，拒绝隐式扩展。

## 影响与迁移

计算函数独立放在 `core/compass`，静态标签放在 `content/compass.ts`。未来新增盘层应保留当前八方层，使用独立 `layerId`、来源和规则版本，不改变既有角度定义。若规则改变，新增 ADR 和版本化数据，不覆盖历史学习记录。

当前通过 `content/compass-layers.ts` 注册盘层：已复核的八方层可用，二十四山仅以待确认禁用态展示，避免 UI 暗示其角度或流派规则已经确定。
